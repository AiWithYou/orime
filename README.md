# Orime — ComfyUI Canvas

Rustで動くローカル画像制作WebUI。ComfyUIを生成エンジンとして接続し、キャンバスでの画像編集とノード編集を同じ制作の中で行う開発中のプロジェクトです。

## できること

- プロンプト、サイズ、シード、サンプラーを設定して生成。複数LoRAと出力拡大を新しいレシピに追加できます。
- 画像のドロップ、選択ブラシ、消しゴム、マスクの取り消し、ズーム、元画像の確認。
- ボタンひとつで実際のComfyUIノード画面へ切替。同じグラフを保持するため、追加したノードを簡易テンプレートで上書きしません。
- ノードの標準入力を簡易画面に取り出して操作。別ノードから制御される入力は個別にロックします。
- 生成結果の再編集、画像保存、workflow JSONの読込・書出し、レシピ変更前の下書き保存。
- ComfyUIの履歴と照合する生成履歴、指定した生成だけの停止。
- 設定の「画像ツールのテンプレート」から、現在の画像で切り抜き・2倍超解像、SDXLの輪郭指定を開始できます。

基本設定は小さなインスペクターに集約し、ステップ数とCFGを並べて表示します。ブラシ幅は画像下のズーム操作と同じバーにあります。キャンバスでは `Ctrl+Enter` で生成、`Ctrl+S` で保存、`B` でブラシ、`E` で消去、`[` / `]` でブラシ幅、`F` でフィット、`Ctrl+Z` でマスクを戻せます。文字入力中は一文字のショートカットを無効にしています。

画像ツールの必要ファイル：超解像は [RealESRGAN_x2plus.pth](https://github.com/xinntao/Real-ESRGAN/releases/tag/v0.2.1) を `models/upscale_models`、輪郭指定は [control-lora-canny-rank128.safetensors](https://huggingface.co/stabilityai/control-lora) を `models/controlnet` に置き、SDXL Baseを選びます。ノード画面で画像、切り抜き位置、強度、使用モデルを調整できます。MiniMax H3 Funの動画用ControlNetとP-H3の画像用VAEは互換ではありません。

ControlNet、プリプロセッサー、IPAdapter、領域指定などは、対応ノードを接続先のComfyUIに導入してノード画面から利用します。すべてのカスタムノードを同梱・動作保証するものではありません。専用画面を持つ拡張には個別の互換性確認が必要です。

「画像ツール」ではControlNet AuxとKJNodesの画像処理を簡易操作できます。既存のFaceDetailer・IPAdapter・Ultimate SD Upscaleなどは用途別に主要設定をまとめて表示できます。[対応範囲と導入方法](docs/custom-nodes.md)

## 起動

必要なもの: Rustのstable環境、対象モデルに対応したComfyUI、モデル本体。画面のビルド済みファイルは同梱しています。画面を変更する場合はNode.js 22.12以降とnpmも必要です。

1. ComfyUIを `127.0.0.1:8188` で起動します。動作基準はComfyUI 0.45.0 / frontend 1.58.5です。
2. Windowsでは `start-orime.bat` を実行します。初回はRustのビルドを行います。PowerShellからは `./start-orime.ps1`、ブラウザーを開かず起動する場合は `./start-orime.ps1 -NoBrowser` を使えます。
3. `http://127.0.0.1:8199` を開き、「設定」でモデルファイルを選びます。

ComfyUIも同時に起動する場合は `settings.example.json` を `settings.local.json` にコピーし、`python` と `comfyDirectory` を設定してください。既存のComfyUIが応答する場合は重複起動しません。

手動起動:

```powershell
cargo run --release
```

接続先は `COMFY_URL`、画面のポートは `CANVAS_PORT` で変更できます。どちらもローカルPC専用です。Rustは画面配信と接続を担当し、画像生成はComfyUI/Pythonが担当します。Rust化によってモデルの必要VRAMが減るわけではありません。

## モデルと編集方式

| モデル | 生成 | 画像を使う編集 | 塗った範囲だけの編集 |
| --- | --- | --- | --- |
| SDXL | 対応 | img2img | ノイズマスク＋元画像への合成 |
| Anima Base v1 | 対応 | マスク編集 | LLLite用パッチが必要 |
| Anima Preview | 対応 | 非対応 | 非対応 |
| MiniMax H3 Image | 対応 | 指示による画像編集 | 全体生成後に指定範囲だけ合成 |
| MOSS Image | 対応 | 専用編集LoRAが必要 | 全体生成後に指定範囲だけ合成 |

H3/MOSSの範囲指定は、モデルへのネイティブなマスク入力ではありません。元画像と生成結果を合成し、範囲外の画素を保持します。マスクを使う場合、最終出力は元画像と同じ寸法です。

モデルファイルはComfyUI対応形式が必要です。同じモデル名でも別アプリ専用の量子化ファイルは読み込めない場合があります。詳細は [モデル別仕様](docs/model-adapters.md) を参照してください。モデルは同梱せず、個別の配布元の利用条件が適用されます。

### INT8・量子化モデル

生成モデル・テキストエンコーダー・VAEは別々に選択できます。分離型モデルの読み込み精度はComfyUIの `default` を使い、UIからFP16へ強制変換しません。ComfyUI対応のINT8、W4A8、FP8などは、重みの形式と接続先の対応状況に従って読み込みます。量子化名だけで互換性を判定しません。

GGUFなど専用ローダーが必要な形式は、対応カスタムノードを導入し、ノード画面でそのローダーを使用してください。標準レシピのUNETLoaderをGGUFローダーへ自動置換する機能はありません。MiniMax H3欄では互換のP-H3量子化構成も選択できます。フル精度・最大サイズのモデルを使う必要はありません。

Anima 3.8B派生版は標準Animaと異なる構成です。専用ノード・追加エンコーダーが必要なため、通常のAnima欄ではなく、配布元のワークフローをノード画面で使ってください。[3.8B配布元の説明](https://huggingface.co/lylogummy/Anima-3.8B)

## 保存と制限

`data/` に下書きと生成ジョブの参照を保存します。生成画像と入力画像は接続先ComfyUIの保存先に置かれます。workflow JSONだけでは画像・モデル本体は移動しません。

保存は未生成のプロンプト・画像・マスクも含みます。生成用グラフがある場合は標準workflow JSON、まだ作成していない場合や新しいマスク処理が必要な場合はCanvas下書きJSONとして書き出します。どちらも「設定」から開けます。既存ノードに新しい画像・マスク処理を追加する場合は「新規レシピ」を選びます。PreviewImageの一時出力は表示できますが、残す画像はダウンロードしてください。

開発初期版です。任意のノード構成を自動的に簡易設定へ逆変換する機能、画像レイヤー管理、テキスト描画、キャンバス上のドラッグによる切り抜き、複数人利用は未実装です。切り抜きはノードのImageCropから利用できます。キャンバス編集画像は21MPまで、取り消し履歴はメモリ量に応じて上限を設けています。PCのメモリ、GPU、モデルの保存ドライブによって生成速度は変わります。

## 終了

`stop-orime.bat` をダブルクリックするか、`./stop-orime.ps1` を実行すると、このフォルダーの起動スクリプトが起動したOrimeとComfyUIを終了します。生成中の処理も停止するため、必要な結果は先に保存してください。ブラウザーのタブは自動で閉じません。

画面右上の「終了」は、その画面のOrimeと、その起動時に立ち上げた専用ComfyUIを停止します。同じフォルダーで別ポートのOrimeを使っている場合も、画面ごとに終了できます。手動起動したOrimeは自分自身だけを終了します。終了後はタブを閉じてください。停止に失敗した場合は画面から再試行できます。

ランチャーは起動ごとにPID・開始時刻・実行ファイルを `.run/` に記録し、終了時に照合します。既存のComfyUIを借りた場合は、そのComfyUIを引き続き使えます。起動途中でエラーになった場合は、その起動で作成したプロセスを片付けます。日本語を含むフォルダー名にも対応しています。
